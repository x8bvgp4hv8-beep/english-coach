# Напоминания (Cloudflare Worker)

Всё приложение работает офлайном, и это его единственная сетевая часть. Причина простая:
браузер не умеет разбудить сам себя, поэтому в нужный час уведомление должен прислать
кто-то извне.

Воркер хранит **только подписки браузеров** — непрозрачный адрес, два ключа, выбранный час
и код языка. Ни прогресса, ни ответов, ни аккаунтов: он ничего не знает про учёбу и не может
ничего о ней узнать. Подписка удаляется сама, как только сервис пушей сообщает, что браузера
больше нет.

## Развёртывание

Всё, что ниже, делается один раз. Приватный ключ в репозиторий не попадает — он живёт
в секретах воркера.

### 0. Node 22

Wrangler 4.x требует Node ≥ 22, а в системе стоит 20 — без этого шага дальше ничего
не запустится.

```bash
brew install node@22
export PATH="/opt/homebrew/opt/node@22/bin:$PATH"   # формула keg-only, сама не линкуется
node -v                                             # ждём v22.x
```

### 1. Вход в Cloudflare

Версия закреплена намеренно: `wrangler@latest` сейчас не устанавливается — тянет
`sharp@0.35.2`, которой нет в npm.

```bash
cd server
npx --yes wrangler@4.113.0 login                    # откроется браузер
```

### 2. Хранилище подписок

```bash
npx --yes wrangler@4.113.0 kv namespace create SUBSCRIPTIONS
```

Команда напечатает готовый TOML-сниппет с `id` — 32 шестнадцатеричных символа. Вставь этот
`id` в `wrangler.toml` вместо `ЗАПОЛНИТСЯ_КОМАНДОЙ_ИЗ_README` (для `.toml` автозапись
не работает, только для `wrangler.json`) и проверь:

```bash
grep id wrangler.toml                               # плейсхолдера быть не должно
```

### 3. Публикация

```bash
npx --yes wrangler@4.113.0 deploy
```

Напечатает адрес вида `https://english-coach-reminders.<аккаунт>.workers.dev`.

### 4. Приватный ключ

Пара VAPID уже сгенерирована, публичная половина лежит в `wrangler.toml` и в
`web/src/app/push-config.ts`. Приватную вставь по запросу команды:

```bash
npx --yes wrangler@4.113.0 secret put VAPID_PRIVATE_KEY
```

Команда сама создаёт новую версию воркера и выкатывает её — повторный `deploy` не нужен.

Если пару когда-нибудь придётся создать заново:

```bash
node -e 'const {subtle}=globalThis.crypto;
subtle.generateKey({name:"ECDSA",namedCurve:"P-256"},true,["sign","verify"]).then(async kp=>{
  const jwk=await subtle.exportKey("jwk",kp.privateKey);
  const raw=await subtle.exportKey("raw",kp.publicKey);
  console.log("VAPID_PUBLIC_KEY  =",Buffer.from(raw).toString("base64url"));
  console.log("VAPID_PRIVATE_KEY =",jwk.d);
});'
```

Публичный — 65 байт с префиксом `0x04`, приватный — base64url от 32 байт, **не** PEM.
Новый публичный ключ обязательно вписать в **оба** места: `wrangler.toml` и
`web/src/app/push-config.ts`. Иначе браузер подпишется на один ключ, а воркер подпишет
пуш другим, и сервис пушей будет отвечать 403 на каждую попытку.

### 5. Адрес воркера — в клиент

Вписать URL из шага 3 в `PUSH_ENDPOINT` в `web/src/app/push-config.ts` и закоммитить —
клиент пересоберётся и выложится сам. Пока строка пуста, экран настроек честно пишет
«сервер не подключён», а кнопка включения не рисуется.

## Проверка

```bash
npx --yes wrangler@4.113.0 tail                                          # живой лог
npx --yes wrangler@4.113.0 kv key list --binding SUBSCRIPTIONS --remote  # кто подписан
npx --yes wrangler@4.113.0 dev --test-scheduled                          # затем открыть
                                                  # http://localhost:8787/__scheduled —
                                                  # прогоняет рассылку, не дожидаясь часа
```

`--remote` обязателен: без него команда читает **локальное** хранилище и всегда печатает
пустой список, что выглядит как «никто не подписался».

Все отказы пуш-сервиса пишутся в лог с телом ответа. Самый частый на первом запуске —
403 при несовпадении пары VAPID; без строки в логе он был бы неотличим от тишины.

## Ограничения бесплатного тарифа

Упор будет не в число запросов, а в процессорное время: на free-плане 10 мс CPU на вызов,
включая cron. Один пуш стоит примерно 0,5 мс — то есть около двадцати получателей в один
и тот же час. Вторая стена рядом: 50 исходящих запросов на вызов. Для нескольких человек
запас есть, для рассылки — нет.

Расписание срабатывает каждый час и шлёт уведомление только тем, у кого совпал **местный**
час: браузер при подписке сообщает свой сдвиг относительно UTC, поэтому родственник в
другом часовом поясе получит напоминание в своё время. Сдвиг пересылается заново при каждом
запуске приложения — иначе после перехода на зимнее время напоминание приходило бы на час
раньше. Часовые пояса с получасовым сдвигом (Индия) получат уведомление в :30.

## Как это выглядит у пользователя

Настройки → «Напоминание» → выбрать час → «Включить». На iPhone это работает **только**
у приложения, установленного на экран «Домой»: в обычной вкладке Safari разрешение на
уведомления не выдаётся, и экран настроек честно об этом пишет.

Слово «включено» на этом экране означает, что сервер подтвердил подписку ответом 2xx.
Если он не ответил, экран говорит «сервер не принял» — но никогда не показывает включённым
то, чего на сервере нет.
